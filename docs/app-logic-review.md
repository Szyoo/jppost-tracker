# 应用逻辑梳理与不直观点分析（2026-07-19）

基于 main（含 07-17 前端重构）的全量代码走读，供后续重构讨论用。

## 一、当前逻辑全景

### 系统部件

```
浏览器 ──HTTPS──> Flask Web 控制台（app.py，常驻）
                      │ 启动/停止（子进程）
                      ├──> tracker.py（轮询脚本，一个进程管所有用户）
                      ├──> Bark Server（VPS 形态下是独立容器，控制台按钮无效）
                      └──> 保活线程（Render 遗产，VPS 上无用）

tracker.py ──每秒──> SQLite（读所有 tracking_enabled=1 的账号）
           ──到期──> 日本邮政官网抓取 ──状态变化──> Bark 推送
```

### 数据模型：`account` 一行身兼两职

| 登录身份字段 | 追踪任务字段 |
|---|---|
| username / password / role / login_enabled | tracking_number / check_interval / bark_keys / tracking_enabled |

### 一条推送成立的 4 个前置条件

1. 账号填了单号；2. 账号开了"启用追踪"；3. 账号填了 Bark Keys；
4. **管理员手动点过"启动"追踪脚本**（全局开关，重启后不自动恢复）。
前三个是每用户的，第四个是全局的且普通用户不可见、不可控。

## 二、不直观的根源（按严重程度）

### 🔴 1. "账号"承载了两件不相干的事
- 一个账号只有一个 `tracking_number`，同时追踪两个包裹做不到（新单号覆盖旧的进历史档案）。
  追踪任务应该是独立实体（一人 N 任务），现在是"一人一格"。
- 列表里混着真人用户、admin（也带追踪字段）、`legacy-user-*`（不可登录的迁移档案），都叫"用户"。
- "启用追踪"ד允许登录"的组合含义没有任何地方解释。

### 🔴 2. 管理员首页打开就在"编辑别人"
- 首页默认选中第一个**非 admin** 用户（`pickDefaultUserId`），admin 看到的"当前账号"是别人。
- 首页表单与"用户管理"页共享同一个 `userForm`，半成品编辑跨页残留。
- 首页定位不清：既是仪表盘又是编辑器。

### 🔴 3. 全局"启动脚本"是隐形门闸
- 用户保存单号后页面显示"追踪启用中"，但脚本没启动就什么都不会发生，门户页无提示。
- 每次容器重启后脚本都是停的（AUTO_START_TRACKER 被停用），必须有人登录手动点。
- 脚本崩了不会自动重启。

### 🟠 4. 三个"Bark"概念糊在一起
- 首页并排：本地 Bark 子进程启停（VPS 下是死按钮）、公网健康状态（"冷启动中"是 Render 文案）、
  用户 Bark Keys（在另一页）。"Bark 未启动"红点在 VPS 形态下是误导。

### 🟠 5. Render 遗产未清理
- 保活线程/PUBLIC_URL/冷启动文案在 VPS 形态下全部无意义，仍占据 UI。

### 🟡 6. 系统设置 = 原样暴露 .env
- 内部变量名直接当表单；保存提示"将在脚本下次启动时生效"**已经不对**——tracker 每轮重读
  .env，Bark 地址即时生效；APP_PORT 又需重启 Web。同表单字段生效时机不一且提示错误。

### 🟡 7. 缺少"发生了什么"视图
- 多用户轮询结果混在 Tracker 原始日志靠 `[显示名]` 前缀区分；普通用户只有
  `last_tracking_info` 一行，无推送历史。

### 🟡 8. 管理员没有自己的门户
- admin 改自己的 Bark keys 要去用户管理里选中自己；普通用户反而有专属页。

## 三、重构方向（已与用户对齐）

1. **拆"用户"与"追踪任务"**：account（身份+Bark 设备）与 tracking_task（单号+间隔+开关+归属），
   一人多任务。大手术，单独规划。
2. **追踪脚本去掉手动开关**：Web 启动即拉起 tracker、崩溃自动重启，"有启用任务就在跑"。
3. **首页改纯仪表盘**：任务状态一览，编辑收进详情；admin 也用"我的"页管自己。
4. **按部署形态裁剪 UI**：VPS 形态隐藏本地 Bark 启停/保活卡片，修正文案。
5. **系统设置场景化分组**，标注每项生效时机，修正错误提示。

**第一刀（2026-07-19 决定）：先做 2 + 4**（消灭隐形门闸 + 死按钮，改动小收益大）。
